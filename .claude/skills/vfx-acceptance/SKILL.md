# 特效：做完整、驗收到位

使用者要求「所有特效要做完整（打到敵人的效果、持續傷害的特效等等全部！）」。最容易漏的不是主武器，而是「事件」：命中、持續傷害的每一跳、打倒、燒傷中、落點、大招的持續期間。所以先盤點事件，再動手。

## 1. 盤點事件（不靠記憶列清單）

畫面的來源（都在 `Run` 上，畫面端用自己的游標讀，不改模擬）：

| 來源 | 內容 |
|---|---|
| `run.feed`（HitFeed） | 每一下命中：x、z、傷害、暴擊、`dot`（持續傷害的一跳） |
| `run.deathLog`／`deathHead` | 每次打倒：x、z、種類（一般／精英／頭目）、體型 |
| `run.tech` | 燃燒地、燈油（`oilShow`）、火柱、火種、爆開（`flashLife`、`flashKind`，含鬼火雨落點）、環內推開（`innerHits`）、河童的漩渦、水痕、水域… |
| `run.lastCast`、`frenzyUntil`、`shieldUntil` | 大招發動與持續 |
| `run.projectiles` | 投射物（`gen` > 0 是碎片） |

對照 `docs/30-vfx-ukiyoe.md` 第 ⑩ 節的「事件 → 樣子」表，新屬性（水、雷…）照同一張表逐列做完，表上每列都要有。

## 2. 架構（照火的做法）

- 數字放 `src/data/vfx.ts`；顏色放 `src/art/palette.ts`；著色器材質放 `src/art/`；池放 `src/render/`。
- 一個屬性用**一個實例化網格**畫所有片（火舌、火星、煙、閃光用 `aInfo.z` 分種類），火光另一個加法混合的網格。**熱路徑不 new**；隨機用自己的小亂數產生器（不碰遊戲的 Rng）。
- 命中與打倒的反應寫成獨立的類別（像 `src/render/fireReact.ts`），每幀有上限、落後太多跳到最新。
- 減少特效：數量乘 `feel.pops`。
- 著色器字串裡的註解用英文（原始碼掃描不准字串裡有中文）。
- 平的光片會被起伏的地形切出硬邊：頂點沿視線往鏡頭拉近，**不要關深度測試**（關了會把光畫在角色身上、角色被洗白）。

## 3. 特效目錄（驗收主工具）

```bash
NODE_PATH=node_modules node scripts/shots/vfx-catalog.mjs <標籤> [妖怪] [只跑哪幾格，例 10,11]
# → screenshots/vfx-<標籤>.png（4 欄）
```

- 每格：開新局、給技法（`evolve` 看進化後才有的效果）、放一排人類、跑到畫面上真的有特效才凍結截圖。格子選項：`tech`、`evolve`、`ult`、`kill`（打得死）、`elite`、`minFx`（隔一陣子才出手的招，例：火柱 70）。
- **單元測試 `tests/unit/vfxCoverage.test.ts` 守著**：換成新風格的妖怪，目錄一定要有命中、打倒一般／精英、牠每一個大招的格子。新角色換特效時先補格子。
- **逐格讀**：火有沒有往上竄、有沒有火星、顏色會不會像泥巴（煙太暗在夜晚會像一塊塊泥巴）、角色有沒有被光洗白、該出現的東西真的在畫面裡嗎。格子是空的或少了東西，先用 `__game.fxStats` 看是哪一種沒畫，不要猜。
- 目錄的坑：`setCamera` 會讓時間跑 1 秒（鏡頭在開頭就設好了，不要在凍結後再設）；`clearEnemies` 會關掉生成。

## 4. 效能

- `p1`（`scripts/regress.mjs --only p1`）：手機 draw call ≤ 80、遊戲中程式數不增加。多一個網格就多一次繪製——超過預算先用 `__game.fxVisible(火, 光)` 在同一刻開關量出真正的來源，再決定（例：最省畫質不畫火光）。**不要先放寬預算。**
- 新材料要在開局就加進場景（預編譯），不要遊戲中途才建。
- 打包後的測試頁也跑一次 p1（publish-test-page skill）。

## 5. 回報

送目錄整張（或重拍的幾格）＋手機實戰 1～2 張。說清楚：哪些事件有效果、哪些還沒做（例：雷屬性大招維持舊樣子）、真機幀率沒量。
