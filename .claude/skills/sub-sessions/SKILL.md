# 子代理與子 session：什麼時候開、開哪一級

使用者（2026-11-16）：「自己可以判斷必要時要開哪些 sub session 輔助你的開發，並留意開的 session 的等級以及 effort，以較省 token 方式來進行。」——這是長期授權：不用每次問，但每次都要算過划不划算。

每個子代理都是「冷啟動」：它看不到這段對話，要重新讀檔才知道我已經知道的事。所以**預設自己做**；只有下面三種情況開了才省：

1. **產出很長、我只要結論**：跨很多檔的搜尋、很長的紀錄、網路研究。讓它讀，我只收十幾行。
2. **真的能平行、彼此不相干**：我在做 A，它做規格明確的 B。
3. **這台機器跑不動的平行工作**：這個容器的記憶體是所有指令共用的，同時開兩個瀏覽器工作會被系統砍掉（發生過）；重的瀏覽器工作要平行，只能開雲端子 session（它有自己的機器）。

開之前先自問：**自己做要幾次工具呼叫？少於大約 8 次就自己做。**

## 開哪一級（Agent 工具的 `model`、`effort`）

| 工作 | 開不開 | model | effort |
|---|---|---|---|
| 找一個符號、看兩三個檔 | 不開，自己 Grep／Read | — | — |
| 大範圍搜尋（很多檔、名字不確定），只要「在哪裡」 | 開 `Explore` | haiku | low |
| 很長的紀錄整理成表（回歸、模擬輸出） | 先用 grep／sed；真的太長才開 | haiku | low |
| 網路研究同類遊戲（設計審查卡要的） | 開 1 個，要求每一點附來源連結、查不到就寫查不到 | sonnet | medium |
| 規格明確的獨立實作（補單元測試、照範本加目錄格子、掃描腳本） | 可以開；會改檔就加 `isolation: "worktree"` | sonnet | medium |
| 大批改動後的第二雙眼睛（改到模擬核心或超過約 400 行） | 開 1 個審查 | sonnet | medium（模擬核心才用 high） |
| 設計判斷、跨系統的決定、原因不明的除錯、平衡取捨 | **不外包**，主 session 自己做 | — | — |
| 給使用者的回報、最後的截圖逐張檢查 | **不外包**（規則要求我自己看） | — | — |

- 能用小的就用小的：haiku → sonnet → 和主 session 同級（不指定 `model`）。同級的子代理只在「小的做過、做不好」時才用。
- `effort` 不設 xhigh／max，除非使用者明講。
- `subagent_type: "fork"` 會把整段對話帶過去、用主 session 的模型——最貴，只在「一定要我現在全部的脈絡、而且產出很長」時用。
- 同一個子代理的後續問題用 `SendMessage` 接著問，不要重開一個。
- 同時最多 2 個；有瀏覽器的工作在這台機器上一次只跑一個。

## 雲端子 session（`create_session`）

只給「獨立、要跑很久（約 30 分鐘以上）、而且會吃記憶體」的工作：例如整套回歸、大量的模擬掃描，同時我在主 session 繼續做別的。它要重新 clone 和安裝，所以短工作不划算。

- `model` 用 sonnet 級、`effort` low 或 medium；`permission_mode` 不要用 plan（沒人按核准會卡住）。
- 任務單寫明：不准推 main、不准發佈 Artifact、不改 `src`（除非任務就是改）；結果寫在最後一則訊息。它不一定會主動回報，用 `get_session`／`list_events`（`kinds: ["assistant","result"]`）去讀。
- 回報時把開過的子 session 列給使用者（他可以自己關掉）。
- **這條路還沒有實際用過**；第一次用時把踩到的坑補進這份文件。

## 任務單（省 token 的關鍵）

它什麼都不知道，但也不需要知道全部。寫成自己看得懂的一小段：

```
目標：<一句話>
先讀：<檔案路徑，最多 3～5 個；不要叫它「了解整個專案」>
做法／指令：<要跑的指令，或要找的東西>
不能動的決定：<docs/14 已決定區裡相關的那幾條；不相關就寫「不涉及設計決定」>
不要做：不提交、不推送、不發佈、不改任務以外的檔
回報：結論放第一行；證據用 檔案:行號 或指令輸出的關鍵幾行；總長 ≤ 15 行
```

## 收回來之後

- 子代理的結論是**線索**，不是事實：要寫進回報或文件的關鍵數字、「修好了」這種話，我自己抽驗一次（規則：原因沒查清楚就不要說修好了）。
- 會改檔的子代理：我看過 diff、跑過相關測試才併進來；提交一律由主 session 做。
- 回報給使用者時講一句：開了幾個、各是哪一級、做了什麼。沒開也不用特別講。
