# 30 技法特效重製：浮世繪風格、更華麗、屬性要有屬性的樣子（設計審查卡；Q59 照預設，**第一批（火）已實作 D90**）

> 使用者 2026-11-15：「有安排所有攻擊特效的重製嗎？要更有浮世繪風格，更華麗，屬性要更有屬性的特色（水更像水，火有燃燒的感覺）」

## ① 一句話結論
**有排，但只做了一半**（D85 水墨第一批），而且你這次要的是**浮世繪＋華麗**，和 D85 的「水墨：墨黑＋主色＋紙白、有限色」方向不同。建議：**以浮世繪取代水墨當作特效的主風格**（保留「墨線描邊」當輪廓，所以 D85 的筆觸貼圖不白做），先做**火與水**（提燈小僧、河童），再做大招，最後才是之後的角色。

## ③ 浮世繪的語彙（**我的理解**；網路搜尋沒有找到浮世繪火焰／浪頭畫法的資料，這一節是我對木版畫的認識，沒有逐項查證來源）
- **輪廓**：深色線描邊、色塊平塗（不是柔邊光暈）。
- **木版的漸層（ぼかし）**：色塊邊緣由濃到淡的暈染，不是發光。
- **圖樣化的自然**：浪用「青海波」（一圈圈同心弧）與葛飾北齋式的**浪頭——浪尖像爪子一樣的泡沫**；火用層層捲曲的**火焰紋**（舌狀、往內捲）；雲霞用橫向的帶狀；雷用折線。
- **華麗**：金色的點與箔（金砂子）、多層疊色、花瓣／楓葉點綴。

## ④ 各屬性的樣子（建議）
| 屬性 | 形狀語彙 | 顏色（外→內） | 動態 |
|---|---|---|---|
| **火**（提燈小僧） | 層疊的**捲曲火舌**（火焰紋）往上竄、火星（火の粉）往上飄、地上是燒焦的痕跡加舔著的小火舌、煙用橫向霞帶 | 暗紅描邊 → 朱 → 橙 → 山吹黃 → 白芯 | 火舌搖擺、尖端分叉、火星往上飄 |
| **水**（河童） | **浪頭帶泡沫爪**、地上一圈圈青海波（水面漣漪）、水滴是帶高光的淚滴、水流是帶白色泡沫線的帶狀 | 藍墨描邊 → 群青 → 水色 → 白泡 | 浪往前捲、漣漪向外擴、水滴噴濺落下 |
| 之後的角色 | 風＝渦捲雲紋、雷＝折線、土＝岩塊與沙煙（赤鬼做的時候再設計） | — | — |

「燒起來」的關鍵是**形狀會動、會往上、尖端會分叉、有火星**；「像水」的關鍵是**有波紋、有泡沫、會捲、會濺**——這兩組是這張卡真正新增的東西，不只是換顏色。

## ⑤ 技術與限制
- 一樣全部程式產生（canvas 貼圖：火舌、浪爪、青海波、淚滴、火星、金砂子、描邊），不用外部圖檔。
- **華麗 ≠ 滿螢幕**：畫面上同時有幾百隻敵人；日常小技法要**清爽可讀**，華麗放在**大招與進化技法**這類少見的時刻（建議，見第 ⑥ 件）。設定畫面的「減少特效」也要照樣管用。
- 效能：手機 draw call 目前約 51～53／80（換成 Blender 角色後有空間了，值得重新量），著色器要預編譯；每種元素的貼圖合進同一張圖集。
- **和 Q57（像素風 vs 乾淨卡通）有關**：浮世繪的描邊與漸層在像素化之後會被吃掉；乾淨卡通畫面（`?look=cel`，目前測試頁的預設）比較合。**建議先確定 Q57 再做**，否則可能做兩次。
- 要先跑一次 sim？不用——只改畫面、不改數值。

## ⑥ 要你拍板的事（附預設）
1. **風格**：**以浮世繪取代 D85 的水墨**（保留墨線描邊）。預設：**是**。（另一個選擇是兩種並存，但會讓畫面的風格不統一，我不建議。）
2. **華麗放在哪**：預設：**大招、進化技法、頭目戰這類少見的時刻特別華麗（金砂子、多層疊色）；日常技法清爽、只有「屬性的樣子」**。（另一個選擇是全部都華麗，我擔心 400 隻敵人加上滿螢幕特效會看不清楚、手機也吃力。）
3. **順序**：預設：**先做剩下三隻敵人（足輕、弓手、退魔僧，約 1 天），再做特效；特效先火＋水（約 3～4 天），再大招（約 1 天），最後效能與回歸**。

## ⑧ 這次的驗收（照 docs/29 的精神：不靠「看起來還行」）
- **轉檯圖式的特效目錄**：每種技法一格、固定鏡頭、固定時間點，排成一張（新工具 `scripts/shots/vfx-catalog.mjs`），回報時整張送出。
- **數字檢查**：同時存在的特效物件上限、每幀新配置為 0、draw call 預算（p1）。
- **「像火／像水」的自我審查清單**：火有沒有往上竄、有沒有火星、尖端有沒有分叉；水有沒有漣漪、有沒有泡沫、有沒有濺。
- 誠實的限制：好不好看、華不華麗最後要你看。


## ⑨ 第一批：火（D90，2026-11-15，使用者「照預設開始」）
**做了什麼**
- 共用：`src/art/flame.ts`（一個著色器材質同時畫火舌與火星）、`src/render/fireFx.ts`（物件池，每幀 begin → flame()/emit() → end）、`src/data/vfx.ts`（每隻妖怪的特效風格與所有數字）、`palette.flame`。
- **火舌**：只繞垂直軸面向鏡頭的一片；著色器畫出下寬上尖、上半部分叉成 2～3 條、尖端往一邊勾（浮世繪的火焰紋）、整條搖、雜訊往上捲動；顏色是平塗色帶（暗紅描邊 → 朱 → 橙 → 山吹 → 白芯），快熄時色帶往外縮只剩紅與暗紅。剪影式透明（不用排序）。
- **火星**：小菱形往上飄、左右晃、變暗；減少特效（`?fx=low/off`、系統的減少動態）時按比例少噴。
- 提燈小僧全部換成火：主武器（飄著的火）、繞身的燈籠環／衛星燈／開路燈（拿掉紅色墨團球）、業火（焦痕＋幾條舔著的火舌＋火星）、鬼火柱（沖天大火＋兩側副火＋大量火星）、火種、燈油（頭上的火）、爆開（一圈先竄高再縮的火舌＋一把火星）、護身火（身邊一圈小火，充好時竄高）。
- 河童仍是 D85 的水墨（第二批換成水）。
- **一次繪製**：火舌與火星同一個實例化網格（上限 320＋160）；著色器在開局預編譯（p1：遊戲中程式數不增加）。
- 驗收工具：`scripts/shots/vfx-catalog.mjs <標籤> [妖怪]`——每種技法一格、跑到畫面上真的有特效才截圖（第一版用固定步數，一半的格子拍到空檔）。

**驗證了什麼**：特效目錄 9 格逐格看過（`vfx-f2`）；回歸 p1、v1、v2、y1、f1、u1 通過；單元測試全過。
**還不夠好／沒覆蓋**
- 遠看（遊戲距離）主武器的火偏小，要你在手機上看會不會太不顯眼。
- 火柱的頂端在一般鏡頭下會被切掉（很高）；
- 燃燒地的焦痕在夜晚草地上不太明顯；
- 命中敵人時沒有另外的火花（擊殺的墨點還是 D85 的）；
- 大招還是舊的（第四批）；
- 真機幀率沒量（火舌的片段著色器有雜訊運算，很多火同時在畫面上時是主要的成本）。

## ⑩ 火的完整版（D91，2026-11-15，使用者：「火可不可以再精緻且動態華麗一點，所有特效要做完整（打到敵人的效果、持續傷害的特效等等全部！）」）
**先盤點「所有會產生畫面的事件」再做**（不靠記憶列清單）：命中回報 `Run.feed`（武器、技法、持續傷害的每一跳都走 `weaponHit`）、打倒紀錄 `Run.deathLog`、技法狀態（燃燒地、燈油、火柱、火種、爆開、鬼火雨落點、環內推開）、大招 `Run.lastCast`／`frenzyUntil`／`shieldUntil`。逐一對到下面的效果：

| 事件 | 火的樣子 |
|---|---|
| 直接命中 | 一朵往外炸的短火＋往外噴的火星＋一圈光；暴擊更大、加金色閃光（きら） |
| 持續傷害的一跳（燈油、燃燒地；`HitFeed.dot`） | 身上竄一下的小火苗＋一顆火星（比直接命中安靜） |
| 打倒（一般／精英／頭目三級） | 竄起的一團火＋飛出去的小火團＋火星＋煙＋地上火光；精英、頭目加金色閃光與一圈往外倒的火舌（火的妖怪不再畫 FeelFx 的墨點：重複、又多一次繪製，見下面 p1） |
| 燒傷（燈油）持續中 | 身上繞著 3 條火舌（不是只有頭頂一朵）＋冒煙＋掉火星＋光暈 |
| 燃燒地 | 原本的火舌＋火星，加冒煙、會呼吸的地上火光 |
| 火種 | 快爆時引信的火星越噴越多、地上的光越來越亮 |
| 爆開（火種、火柱落地、鬼火雨落點） | 一圈火舌＋火星＋飛出去的小火團＋地上與空中的光＋一朵煙 |
| 鬼火雨 | 每顆從 7 公尺高落下的火（0.2 秒），落地爆開 |
| 鬼火柱 | 加地上火光、半空光暈，快熄時冒黑煙 |
| 燈籠環、衛星燈、開路燈、鬼火 | 加光暈與小火星 |
| 燈籠環的環內推開 | 貼地一圈往外倒的火＋往外噴的火星＋地上的光 |
| 大招：大火圈（nova） | 中央竄起火柱、往外噴火星與一圈煙、一圈火舌往外擴散到大招半徑、地上大片火光 |
| 大招：狐火之舞（frenzy） | 持續期間幾團火繞著身體螺旋往上飄、火星、腳下的光 |
| 大招：護罩（bulwark） | 發動時小一號的火圈擴散；持續期間一圈火牆繞著轉（取代舊的發光球罩） |

**火舌本身更精緻、更會動**：整條會「呼吸」（高度忽高忽低的閃爍）、尖端會有一小團火脫離往上飄走、朱與橙的交界加一條暗紅的「雕版線」（木版畫的刻線）。
**新的共用零件**（`fireFx.ts`）：粒子池（火星、金色閃光、煙＝浮世繪的捲雲、飛出去的小火團、短暫的火焰；420 個，和火舌同一次繪製）、火光（加法混合、很淡，地上一片或面向鏡頭的光暈；另一次繪製，不做深度測試——平的一片會被起伏的地形切出硬邊）。全部預先配置、熱路徑不 new；減少特效時按 `feel.pops` 打折。
**驗收工具**：`vfx-catalog.mjs` 加到 16 格（命中、打倒一般／精英、燒傷、鬼火雨、三種大招）；第 4 個參數只跑指定的格子（例：`... f4 chochin-kozo 10,11`）。開發介面加 `evolveTech(id)`、`spawnAt(..., hp)`。
**會擋下來的檢查**：`tests/unit/vfxCoverage.test.ts`——換成新風格（不是 ink）的妖怪，目錄一定要有命中、打倒一般／精英、與牠每一個大招的格子；拿掉一格就紅（用 `VFX_CATALOG` 指向拿掉一格的複本驗證過）。河童換成水的時候，這個測試會逼著把牠的格子補齊。

**效能（p1）**：手機橫式滿場那一刻 draw call 81 > 預算 80（之前 79）。**第一次我寫「原因是重複的墨點」並拿掉了火的妖怪的墨點，重跑還是 81——那個推論錯了**。改成直接量：開發介面 `fxVisible(火, 光)` 在同一刻開關，火的網格 1 次、火光 1 次，不含火是 79；所以多出來的 2 次就是火本身（以前那一刻火的網格剛好是空的）。處理：p1 用的是畫質最省（`q=4`），**火光在畫質最省時不畫**（`FIRE_FX.glow.offAtQuality`；火光是裝飾，最省等級本來就是給跑不動的手機）。**沒有放寬預算。** 拿掉墨點那一步留著（和火的打倒效果重複；f1 改讀「墨點＋火的打倒效果」的總數 `popsActive`，還是真的在測）。開發介面另外加了 `drawList()`（看得到的物件清單）。
**火光的深度**：第一版關掉深度測試（避免平的光被起伏的地形切出硬邊），結果光畫在角色身上、護罩那格角色被洗白；改成頂點沿視線往鏡頭拉近 0.3～0.6 公尺，深度測試打開。
**目錄的坑**：`setCamera` 會跑 `game.frame(1)`（時間往前 1 秒），凍結後才設鏡頭會錯過短效果（大火圈 0.95 秒，第一次拍不到火圈）；鏡頭改在開頭設。開發介面 `fxStats`（每幀火舌／粒子／光各幾個）就是查這個用的。

**還沒做**：雷槍（`thunderSpear`，通用大招，屬性是雷不是火）維持舊樣子；河童（第二批，水）照同一張表做完整。
