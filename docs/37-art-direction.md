# 37. 美術方向與建模師（使用者 2026-11-27）

> 使用者：「美術部分，我想要做成如圖等級的程度，所有紋理、細節、材質都要這麼精緻，並請你開一個專業建模的 session，請他擔任建模師，所有地圖、角色、怪物等都請他自主研究設計並改善以及自動測試，相關規則都交給他維護，並最後你來審核，你可以自主調動他！」
> 同一天：素材授權放寬到 CC0、CC-BY、OGA-BY（要標示作者）。

## 1. 目標畫面（使用者給的參考圖，用文字描述；圖是別家商業遊戲的截圖，**不放進這個公開的版本庫**）

一張夜晚的日式老街（大正、昭和初期的感覺）第三人稱遊戲畫面：
- **場景**：左邊是紅磚牆（每塊磚有凹凸、灰縫、髒污），右邊是木造町屋（木紋、格子窗、屋簷層次），地上是石板路與排水溝；街燈與燈籠發暖黃光，遠處有霧，天空是深藍的夜。**每個表面都有貼圖與法線細節，不是單色塊**。
- **光**：月光的冷藍環境光＋燈的暖色點光，角色有柔和的邊緣光，遠景有高度霧與空氣感；整體柔和、不刺眼。
- **角色**：Q 版大頭（頭約佔身高 40～45%），**臉是畫出來的**（大眼睛有虹膜、多層高光、眼皮與睫毛線條；腮紅），衣服有布料紋理、皺褶、滾邊、蝴蝶結、花紋，表面平滑（細分過的曲面，不見多邊形稜角）；一隻狸貓系角色手提發綠光的燈籠，一個穿蕾絲洋裝的娃娃浮在空中、有半透明的分身。
- **小道具**：老式轉盤電話（金屬與木頭材質分得清楚）、木招牌、燈柱——每個都有材質區分與磨損。
- **介面**：深色半透明面板、斜切邊角、角色頭像框有彩色外框、按鍵提示圖示；乾淨、資訊少而清楚。

**要達到的程度**：角色與場景都要有「貼圖＋法線／細節＋材質區分」，不能只是頂點色色塊；但仍是我們的和風乾淨卡通（D89）、Q 版妖怪（D88），**不是照抄那款遊戲的角色或場景**（CLAUDE.md：不做現有遊戲的翻版）。

## 2. 建模師子 session 的職責（使用者授權：自主研究、設計、改善、自動測試、維護相關規則）

- **範圍**：所有地圖（地形、貼圖、植物、建築、道具、天空、光）、玩家角色（含化身三階）、人類敵人與頭目、要素與補給品的模型、特效的貼圖素材、介面的視覺（面板、按鈕、圖示的美術）。
- **不動**：玩法與數值（`src/game`、`src/systems`、`src/data` 裡的平衡數字）、存檔格式、狀態機。要動渲染或資料裡的「外觀參數」（`src/data/look.ts`、`ambience.ts`、`vfx.ts`、`palette.ts`）可以。
- **維護的規則**：`docs/29-model-acceptance.md`（模型驗收）、本文件、`tools/blender/` 的稽核（`audit.py`）、`scripts/shots/` 的驗收截圖腳本；**新增規則要同時有自動檢查**（CLAUDE.md 既有原則）。
- **工具**：Blender（`pip install --target <暫存目錄> bpy==5.3.0`，約 1.1 GB；`npm run model:build`、`model:turnaround`）、外部素材（`scripts/assets/fetch-oga.mjs`、`tools/blender/convert.py`、`scripts/shots/candidates.mjs`；可用網站：opengameart.org、ambientcg.com、api.polyhaven.com／dl.polyhaven.org、quaternius.com；**不偽裝瀏覽器繞過網站的阻擋**）。

## 3. 必守的限制（建模師不能自己放寬，要改先跟主 session 講、附證據）

- **效能**：手機 draw call ≤ 80（`regress --only p1`；目前已 87，是既有問題，**不能再變多，最好帶回來**）、遊戲中著色器程式數不增加；**敵人一隻 ≤ 700 三角形**（場上最多 200 隻；要提高必須附 p1 量測）；玩家角色與頭目可以多（建議 ≤ 6000）。
- **測試頁是單一 HTML**（素材內嵌）：目前約 5.7 MB；**整份 ≤ 15 MB**。貼圖用 1024 以下、能共用的共用（貼圖集）、優先用 KTX2／壓縮過的 PNG／JPG。
- **授權**：CC0、CC-BY、OGA-BY；每個檔寫進 `src/assets/LICENSES.json`（`assetLicenses.test.ts` 擋）；標示作者的要列進製作名單（之後做名單畫面）。
- **風格**：和風、乾淨卡通、圓潤 Q 版；不 flatShading、不留銳利的邊；一般關卡是夜晚。
- **玩家看得懂**：遊戲距離（手機直式，角色約 40～60 px 高）下要分得出每種敵人、看得到預告與範圍圈；精緻化不能讓畫面變雜、讓敵人和地面混在一起。

## 4. 工作流程與審核（主 session 審核，使用者授權主 session 自主調動建模師）

1. 建模師在 **`art/modeler` 分支**工作（不准推 main、不准發佈 Artifact、不改主網址）。
2. 每一批（一個角色、一張地圖的一部分、一類道具）完成後：
   - 跑 `npm run typecheck`、`npm test`、`npm run model:build`（稽核全過）、`model:turnaround`、`regress --only p1,e1,e3,e4,y1,o1`（或和改動相關的）、`scripts/shots/` 的改前／改後**同一個鏡頭**對照圖；
   - 推到 `art/modeler`，最後一則訊息寫：做了什麼、改前改後的截圖路徑、p1 數字、測試頁大小、還沒做的。
3. 主 session 拉分支，自己看截圖、跑回歸、量 p1 與檔案大小，**過了才併進 main**、發測試頁給使用者看；不過就把具體問題回給建模師。
4. 主 session 給方向與優先順序；建模師可以提案（研究同類遊戲怎麼做、附來源），但**改到既有決定（docs/14 已決定區）先問主 session**。

## 5. 第一批（試作，先給使用者看方向）

1. **提燈小僧**（玩家，基本型）：貼圖化的臉（畫出來的眼睛與高光）、衣服布料與滾邊、燈籠紙的透光、細分後的平滑曲面；轉檯圖＋遊戲距離。
2. **夜晚地面與一小段街景**：石板路／泥土／草地的貼圖（ambientCG／Poly Haven），一兩個和風道具（石燈籠、木柵欄）；同一個鏡頭的改前改後。
3. 量 p1、測試頁大小，寫進本文件第 6 節。
