## 1. 現況（以程式碼為準，`src/data/techniques.ts`）

**一個玩法層級的畫面**：玩家領一隻妖怪（目前只有提燈小僧），主武器「鬼火」自動發射。升級時三選一，其中約 12% 機率會有一張「技法卡」。

| 項目 | 現況 |
|---|---|
| 技法種類（提燈小僧一池） | **12 種**：狐火分裂、彈跳、歸巢、鬼火雨、燈籠環、護身火、衛星燈、開路燈、業火、火種、鬼火柱、燈油 |
| 一局最多拿幾個技法 | **3 個**（`TECH_MAX`）；鬼火本身也算一個技法，但不佔欄位 |
| 技法等級 | 1～8 級，每級 +12% × 稀有度倍率；卡片帶隨機能力值詞條（條數 凡 1／良 2／珍 3／極 4） |
| 取得機率 | 升級卡的 12%（`TECH_OFFER.chance`），玩家 4 級起；下一級要玩家等級 ≥ 4 + 3 × 技法等級 |
| 進化種類 | **7 種**：兩個技法都到 **5 級**（剛從 8 降到 5）→ 合魂祠或開寶箱選進化卡 → 併成一格、效果 ×1.25、參數換強 |
| 進化有沒有獨有行為 | **沒有**：目前只是「兩個技法各自大幅強化＋省一格」 |
| 一局長度 | 2 關約 20 分鐘；玩家約 37 級；一局抽到的技法卡約 6～10 張 |
| 機器人模擬（20 局） | 技法平均 2.4～2.8 個、等級合計 3.4～7.1、**進化 0.00 次**（機器人不會刻意堆同一組，真人尚未驗證） |

**計畫中（docs/17 M2-3 設計稿）**：再加河童、赤鬼兩隻，各自一池技法（草案各 8 種）＋各自進化（草案各 4 個）。總計會變成：技法 12 + 8 + 8 = **28 種**，進化 7 + 4 + 4 = **15 種**。

## 2. 使用者已決定、不能推翻

- 技法一局最多 3 個、融合（進化）**不限次數**（D53）。
- 鬼火也是技法、納入進化名單（D53）。
- 每一次升級卡都有稀有度；技法卡帶詞條（D53）。
- 適合的法具**沒有加成**，只是提示（D53）。
- 招式養成層數要精簡：聯動已刪（D51）、大招改局外裝配（D52）。
- 新妖怪的名字、數量、解鎖流程：五行與種族留 M3／M4（D35）。

## 3. 我目前的看法（請它挑毛病）

1. **12 種技法偏多但可接受**：一局只拿 3 個、抽到機率低，玩家看不到全部，不會有選擇癱瘓；真正的成本在**設計、平衡、測試的量**，不是玩家的負擔。
2. **7 個進化的問題不是數量，是沒個性**：玩家感覺不到「進化」和「普通升級」的差別。寧可 3～4 個有獨特行為的，也不要 7 個只是數字變大。
3. **進化頻率比數量更急**：材料降到 5 級之後，機器人仍 0 次；要靠試玩確認真人碰不碰得到。
4. **河童、赤鬼各 8 種＋4 個進化建議砍到各 6 種＋2 個**，做出手感再補。
5. **配對規則的風險**：進化要「兩個指定技法」，一局只拿 3 個，配對成功率低；如果進化變成「很難碰到的獎勵」，7 種或 15 種都等於不存在。

2. 進化應該是「少數、有個性、容易碰到」還是「多數、數字型、很難碰到」？理由。
3. 我們「一局最多 3 個技法＋不限次數進化」的組合，會不會讓進化變得**太容易或太難**？
4. 若要砍，**先砍技法還是先砍進化**？哪幾個技法最該先砍（可以看第 1 節的清單，或請它讀 `src/data/techniques.ts`）？
