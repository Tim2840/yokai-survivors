# 26 引入 Blender（設計審查卡，**排程、未實作**，Q53）

> 使用者 2026-11-12：「blender 的引入也要提上日程」。延續 Q47（「不要只用我們目前有的資源，請想別的辦法大大提昇精緻度」）。

## ① 一句話結論
可以做，而且是提升角色與場景精緻度最直接的路；但它會**推翻一條鐵則（CLAUDE.md：「不使用外部模型檔，所有模型用程式碼建出來」）**，並且要先解決「模型誰做」。建議排在這一批（河童新機制、平衡）之後，先做一個**小型試作（1 個角色＋1 個場景物件，約 2～3 天）**確認整條流程走得通，再決定要不要全面換。

## ② 現況
- 所有模型都是 TypeScript 用基本形狀拼出來的（`src/units`、`src/art/shapes.ts`），每隻約 700 個三角形以內；優點是檔案小（整個遊戲單一 HTML 約 0.9 MB）、風格統一；缺點是造型的精緻度有上限（你已經說過不滿意）。
- 測試頁與主網址是**單一 HTML 檔**（Artifact），外部檔案載不進來，模型必須**內嵌**在檔案裡。

## ③ 做法（三條路）
| | A 我用 Blender 的 Python（bpy）寫腳本建模 | B 你（或外包）在 Blender 手動建模 | C 用現成的免費素材（CC0） |
|---|---|---|---|
| 精緻度 | 中上：修改器（倒角、細分、布林）、骨架、頂點色，比現在好一截；但我看不到畫面只能靠算圖檢查 | 最高 | 看素材 |
| 風格一致 | 高（同一套腳本） | 看人 | 低（要挑、要改色） |
| 誰出力 | 我 | 你／美術 | 我挑、你同意 |
| 風險 | 腳本建模的上限仍低於手工 | 你說過你不是美術；外包要錢 | 之前查過：這個環境連不到幾個素材站（kenney、quaternius、itch、opengameart 被擋）；授權要逐一確認 |
- 三條路的下游都一樣：**Blender → 匯出 glTF（.glb）→ 壓縮 → 內嵌進單一 HTML → 遊戲用 GLTFLoader 載入**。
- **我查到的事實**：這個環境裡沒有安裝 Blender；套件庫上有 `bpy`（Blender 的 Python 模組，5.3.0），**還沒有實際安裝、跑過**——能不能在這個環境無頭執行、匯出 glTF，是試作第一步要驗證的事，現在不能保證。

## ④ 要先講的代價
- **檔案大小**：一個帶骨架動畫的 Q 版角色約 100～300 KB（壓縮後）；10 個角色＋場景物件會讓單一 HTML 從 0.9 MB 變成 3～5 MB（Artifact 上限 16 MB，夠用，但載入變慢）。
- **效能**：手機的繪製次數已經 77／80。敵人是 `InstancedMesh`（一種敵人一次繪製）——**帶骨架的模型不能直接這樣畫**，200 隻敵人要改用「頂點動畫貼圖」或維持現在的程式動畫（只換網格）。玩家與頭目（各 1 隻）可以直接用骨架。
- **像素風**：畫面會像素化＋卡通著色，模型太細的細節會被吃掉；重點是**輪廓與比例**，不是面數。
- **鐵則要改**：CLAUDE.md、docs/06（架構）、docs/08（美術）要改成「模型可以用 Blender 做，來源檔（.blend 或建模腳本）放進版本庫」。
- **流程變重**：改一個模型要重跑匯出；測試（三角形數、動畫名稱、大小預算）要新做。

## ⑤ 建議的排程

|---|---|---|

| 1 | 試作：提燈小僧 1 隻（腳本建模＋走路動畫）＋鳥居 1 個；內嵌、載入、像素化後和現在的並排截圖給你比 | 2～3 天 |
| 2 | 你看過試作再決定：全面換／只換玩家與頭目／只換場景物件／不換 | — |
| 3 | 全面換（如果要）：2 隻玩家＋6 種敵人＋場景物件 | 另估（約 2～3 週） |
