# 29 模型驗收：為什麼會出錯、兩道自動檢查（2026-11-14 建立）

使用者 2026-11-14：「你為什麼會犯這個錯，要建立一個檢查方法，避免一樣的錯誤發生。」
指的錯：提燈小僧第三版的**瀏海和後腦頭髮是分離的**（中間露出頭皮）、**五官位置不對**；更早還有「臉很亂」「建模醜」「退回舊造型」。

## 1. 為什麼會犯（我查到的原因，不是藉口）
1. **規則早就有，但沒有東西會擋我。** `docs/08` 第 16 行寫著「每個新模型要從前／側／後／3/4／俯視／剪影看過」，`docs/10` 列了要從舊專案搬的展示間與多角度截圖腳本——**那兩個工具沒有搬過來**。只剩文字的規則，我在趕進度時就沒做。
2. **我只從一個斜前方角度看截圖。** 側面與背面從來沒拍過，所以「後腦是一顆大球、瀏海是另一塊」完全看不到。甚至有一次我以為拍到正面，其實是背面（角度用猜的）。
3. **五官位置是憑感覺填數字。** 沒有任何比例的定義，也沒有量測；「看起來還好」就交了。
4. **我的自我審查在問「有沒有畫面、有沒有報錯」，不是「結構對不對」。** 把縮小的圖掃一眼就寫「乾淨多了」。
5. **用一堆獨立的幾何體「拼」頭髮**，沒有「這幾塊應該是連在一起的」這個概念，也沒有任何檢查會發現它們沒接上。
6. 載入失敗時靜默退回舊模型（已修），所以連「你看到的是不是我做的那個」都沒有保證。

## 2. 第一道：數字稽核（建模時自動跑，不過就不匯出）
`tools/blender/audit.py`，在 `build.py` 合併零件之前呼叫 `audit.run(零件, 規格, 名稱)`；有任何一條不過 → exit 1 → **不會產生 .glb**。

| 檢查 | 怎麼量 | 抓什麼錯 |
|---|---|---|
| A 頭髮連續 | 每 15° 一條經線，從頭頂往下每 3° 射一條線，記錄先打到頭髮還是皮膚；只允許「頭髮…頭髮→皮膚…皮膚」換一次 | 瀏海和後腦之間露出頭皮（這次的錯）；頭頂沒頭髮 |
| B 頭髮厚度 | 頭髮外表面到頭皮的距離 ≤ 頭半徑的 20% | 後腦一顆比頭還大的球、頭盔感 |
| C 五官位置 | 眼睛高度在「髮際線→下巴」的 35～60%；兩眼內側距離 0.7～1.25 個眼寬；左右對稱；嘴在 62～88%、不能和眼睛上下重疊、離下巴 ≥ 8% | 眼睛太低太開、五官擠在一起 |
| D 五官貼在臉上 | 每個五官要和頭的表面相交 | 浮在臉外面、整個埋進頭裡 |
| E 懸空零件 | 每個零件至少和另一個零件相交 | 沒接上的髮束、浮在帽子外面的編線、沒接上的流蘇 |
| F 太細（警告） | 最細的一邊 < 0.012 公尺 | 手機上變雜點的細線 |

- 比例的範圍放在 `audit.py` 的 `RULES`：來源是一般 Q 版設計通則（docs/28 第六節）加上我對各版的量測，**不是哪一款遊戲的官方數字**；覺得太嚴或太鬆就改，並在這裡記一行原因。
- **稽核自己的測試** `tools/blender/audit_selftest.py`：一顆好的頭要通過；一顆重現這次錯誤的壞頭（獨立的瀏海＋後腦球、眼距太寬、嘴擠到眼睛、懸空零件）五項都要被抓到。改規則之後一定要跑。
- **「舊版會紅」的證據（2026-11-14）**：把第三版、第二版的建模腳本拿出來跑同一套稽核——第三版 7 項不過（頭髮在正面 9 條經線上斷開、頭髮厚度 37%、眼睛在 65%、眼距 1.36、嘴和眼睛重疊、嘴浮在臉外、帽子編線懸空）；第二版 7 項不過。
- **它第一次跑就在「我以為已經修好」的第四版上抓到**：眼距 1.27（略超過）、斗笠第二圈編線浮在帽子外面、燈籠流蘇沒接上。

## 3. 第二道：轉檯圖（回報前一定要跑、逐格讀）
`scripts/shots/turnaround.mjs`：9 個固定視角排成一張——正面、右前 45°、右側、背面、左側、左前 45°、俯視、臉部特寫、遊玩視角與大小；沒有 HUD；**從角色真正的面向算起**（`__game.facingDeg`，不再猜角度）。
- 數字抓不到的東西靠這張：這次它抓到「耳朵前面的髮際線有缺口」「燈籠提在臉的高度、從右前方看會擋住臉」。
- 第 9 格是實際遊玩的距離：那個大小下只認得出輪廓與主色，臉看不到——所以**輪廓與配色比臉的細節重要**，細節不要做在遊玩時看不到的地方。

## 4. 流程（之後每個模型、每次改模型都照這個）
```
export BPY_HOME=<裝了 bpy 的資料夾>            # pip install --target <資料夾> bpy
npm run model:build                             # 稽核自我測試 → 建模（含稽核；不過就停）
NODE_PATH=node_modules npm run model:turnaround -- <標籤>   # 要開著 vite；產生 screenshots/turnaround-<標籤>.png
```
1. 稽核不過 → 修到過，**不准用放寬規則或把零件加進例外來過**（真的要例外，寫原因）。
2. 轉檯圖 9 格逐格讀，每格問：頭髮／衣服有沒有斷開或穿模？五官被擋住嗎？從這個角度認得出是誰嗎？
3. 回報時把**整張轉檯圖**送給使用者（不是只挑好看的那一格），並寫出我自己看到的缺點。
4. 新角色：在 `build.py` 給它一份規格（哪些零件是頭、頭髮、眼睛、嘴），沒有頭髮的（河童的盤子、光頭）寫 `bald: True`。

## 5. 這套檢查抓不到的（要誠實）
- **好不好看、可不可愛**：數字只保證「沒有結構上的錯」，品味仍然要你看。
- 動畫中的穿模（走路時手穿過身體）：目前只檢查靜止姿勢。
- 敵人（實例化網格、用程式建的舊模型）還沒有接這套。
- 沒有頭的東西（場景物件）只有「懸空零件」那一條有用。
- 真機上的樣子與幀率。
